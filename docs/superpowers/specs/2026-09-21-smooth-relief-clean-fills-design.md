# Дизайн: гладкий рельеф и чистые заливки (двустороннее сглаживание)

- Дата: 2026-09-21
- Статус: одобрен пользователем (подход A; сегментация областей — этап B, позже)
- Канал обсуждения: мозговой штурм по качеству 3D-картинки из фотографий

## 1. Проблема

При печати детализированных фотографий результат неудовлетворительный:

1. **«Гималаи» и шершавость поверхности.** `buildHeightField` (src/lib/heightmap.ts)
   превращает яркость каждого пикселя в высоту со снапом на слой. Фотографический
   шум и мелкая фактура становятся миллионами ступенек ~0,2 мм — поверхность
   выходит колючей, на краях контрастных областей торчат пики. Сглаживания в
   пайплайне нет вообще.
2. **«Размазанность» цветов.** Median-cut (src/lib/quantize.ts) режет фото на
   4–8 плашек: градиенты и полутоновые переходы внутри областей квантуются в
   мутные смеси соседних тонов, картинка выглядит грязной и нечёткой.

Для геометрических фигур текущий алгоритм подходит; для детализированных
фотографий — нет. Нужен preprocessing: сначала чистые градиентные заливки,
затем из них — картинка для печати.

## 2. Решение: подход A — двустороннее сглаживание в двух точках пайплайна

Новый чистый модуль `src/lib/smooth.ts` — bilateral-фильтр, сглаживает всё,
кроме резких границ: усреднение пикселя с соседями, где вклад соседа зависит
от его яркостной близости к центру. Включается в двух местах:

1. **До квантования.** RGB картинки чистится от шума: median-cut получает уже
   чистые данные → палитра из чистых заливок, границы областей остаются
   резкими. Это идея «сначала градиентные заливки, потом готовая картинка».
2. **Карта рельефа.** Та же карта яркости, из которой строится высота,
   сглаживается с сохранением границ: шум исчезает (нет «гималаев»), а
   настоящие контуры картинки остаются чёткими террасами.

Один ползунок «Сглаживание»: 0 % = как сейчас, по умолчанию ~30 %. Считается
в воркере; на 1024² это десятки–сотни миллисекунд. Характер HueForge
сохраняется: непрерывный тональный рельеф, а не плоские ступени.

Отклонённые альтернативы:

- **B — сегментация областей (mean-shift/суперпиксели) + градиентные заливки:**
  самый «плакатный» результат, но секунды вычислений, большой объём нового
  кода, риск мультяшности. Отложена как второй этап после A.
- **C — только геометрия (плато + пандусы):** проще всего, но убивает
  непрерывный тональный рельеф и не чинит цвета.

## 3. Архитектура

### 3.1 Новый модуль `src/lib/smooth.ts`

Чистые функции без DOM (тестируются в Node, как остальные модули `lib/`):

- `bilateralSmoothRGBA(rgba, w, h, opts)` — bilateral по цвету. Сглаживает
  плоские области и градиенты, сохраняет резкие границы. Альфа не трогается.
- `smoothScalarField(t, w, h, opts)` — тот же bilateral для скалярной карты
  рельефа (0..1): убирает пик-шум высот, сохраняет террасы на контурах.

Сила — одно число 0..1. Значение 0 → функция сразу возвращает вход (нулевой
оверхед, поведение байт-в-байт как сейчас). Внутренние пороги «что считать
границей» у цвета и рельефа свои; наружу торчит только сила.

### 3.2 Врезка в пайплайн (в воркере, точка `quantizeOnce`)

```
rgba ──► [bilateral RGBA] ──► квантование (палитра + indexMap)  ← чистые заливки
                                   │
                                   ▼
                         q.luminance ──► [bilateral скалярный] ──► heightField
```

- Сглаживание RGBA выполняется до квантования: median-cut видит чистые
  данные; работает и в режиме каталога спулов.
- Рельеф сглаживается отдельно и сильнее (свой порог границ): контуры
  остаются чёткими террасами, шум между ними исчезает.
- Дизеринг, ΔE-слияние, тона и Reference 3MF идут дальше без изменений;
  превью и печать согласованы, потому что строятся из одних сглаженных данных.
- Выполняется только на этапе quantize (не при каждом rebuild).

### 3.3 UI и хранение

- Один ползунок «Сглаживание» в секции «Цвета», рядом с «Дизерингом»:
  0–100 %, по умолчанию 30 %. 0 % = ровно текущее поведение.
- Тексты RU/EN в `src/i18n.ts` (+ подсказка «?»): убирает шум и «гималаи»,
  сохраняя границы.
- Настройка едет через существующие каналы: `readOptions()`, undo-снапшоты,
  localStorage, файл проекта `.hueforge.json` (новое опциональное поле —
  старые проекты открываются со сглаживанием 0, обратная совместимость).
- Управление — как у дизеринга: drag → отложенный reprocess, отпускание →
  сохранение.

## 4. Тесты

- `smooth.test.ts`: плоское поле не меняется; резкая граница сохраняется
  (переход остаётся узким); шумная рампа успокаивается при сохранении
  среднего; альфа нетронута; сила 0 = тождество; в скалярном поле плато не
  размывается, одиночный пик убирается.
- `workerProtocol.test.ts`: опция доезжает до quantize; `smooth=0` даёт
  вывод, байт-в-байт равный прежнему.
- `pipeline.test.ts`: сглаженная карта высот имеет заметно меньшую энергию
  градиентов, чем несглаженная.

## 5. Не делаем (YAGNI)

- Сегментацию/mean-shift — этап B, отдельная спека после оценки A.
- Отдельный ползунок для рельефа — один, внутренние пороги разные.
- GPU-ускорение, новые тональные контролы.
