# HueForge Web — дизайн

**Дата:** 2026-09-02
**Статус:** реализовано
**Историческая справка:** документ описывает состояние на дату написания. Часть
решений с тех пор изменилась — рабочее разрешение, диапазон числа цветов и модель
поверхности. Актуальное поведение: [README.md](../../../README.md) и
[CHANGELOG.md](../../../CHANGELOG.md).
**Продукт:** браузерное приложение, превращающее произвольное изображение в
многослойную «филаментную картину» для 3D-печати: загрузка → сокращение до N цветов
(4/8/12/16 или вручную 2–16) → ступенчатая карта высот → скачивание STL или 3MF;
цвет кодируется высотой слоя.

## Исследование и лучшие практики

- **Механика HueForge (проверено):** филаментная картина — стопка тонких цветных
  листов; каждая цветовая полоса лежит на своей высоте и печатается от тёмного
  к светлому (или наоборот), а смены филамента в слайсере на границах слоёв дают
  изображение. Самые высокие поверхности — последний напечатанный цвет.
  (shop.thehueforge.com, snapmaker.com/blog/hueforge-3d-printing, hueforge.wiki)
- **Цвет в 3MF (проверено):** расширения 3MF Core + Materials кодируют цвет
  треугольника через ресурс `basematerials` и атрибуты `pid`/`p1` у `<triangle>`;
  слайсеры (Bambu/Prusa/Orca) читают `displaycolor` для назначения филамента.
  (github.com/3MFConsortium/spec_materials, modelrift.com/blog/multicolor-3mf-export)
- **STL не несёт цвета** (blog.prusa3d.com) → наш STL кодирует цвет геометрически,
  высотой слоя, ровно как HueForge; 3MF дополнительно несёт палитру и порядок
  печати в метаданных.

## Архитектура

```
┌─────────────────────────── Браузер (без сервера) ─────────────────────────┐
│                                                                           │
│  UI (src/ui/main.ts)          Pipeline (src/lib)            Exporters     │
│  ┌────────────────┐   File   ┌──────────────────┐          ┌───────────┐  │
│  │ drop zone /    │ ───────▶ │ loadImage (512px) │          │ exportStl │  │
│  │ options /      │          │      ▼            │  Mesh    │  (binary) │  │
│  │ palette panel  │          │ quantize (median  │ ───────▶ ├───────────┤  │
│  │ canvases       │          │  cut + redmean)   │          │ export3mf │  │
│  └───────┬────────┘          │      ▼            │          │  (fflate) │  │
│          │                   │ sortByLuminance   │          └───────────┘  │
│          ▼                   │      ▼            │                         │
│  ┌────────────────┐          │ buildHeightField  │                         │
│  │ Viewer3D       │ ◀────────│      ▼            │                         │
│  │ (three.js,     │  Mesh    │ buildMesh         │                         │
│  │  OrbitControls)│          │  (watertight)     │                         │
│  └────────────────┘          └──────────────────┘                          │
└───────────────────────────────────────────────────────────────────────────┘
```

- **Фронтенд:** Vite + TypeScript, без фреймворка — для интерфейса достаточно
  нескольких DOM-панелей.
- **Обработка:** чистые функции над типизированными массивами (квантование
  median-cut, поиск ближайшего цвета по redmean, ступенчатое поле высот, сборка
  водонепроницаемого меша) — детерминированные и покрываемые юнит-тестами в Node.
- **Предпросмотр:** `OrbitControls` из three.js; группа модели повёрнута на −90° по
  X, чтобы печать лежала на сетке-«столе».
- **Экспорт:** бинарный STL (80-байтный заголовок + 50 Б на треугольник) и 3MF
  (zip через fflate; вершины дедуплицированы, у каждого треугольника
  `pid="1" p1="materialIndex"`, палитра и порядок печати — в `<metadata>`).

## Поток данных

1. Перетаскивание/выбор изображения → `createImageBitmap` → canvas → RGBA
   `Uint8ClampedArray`, уменьшение до ≤512 px по большой стороне (≈0.29 мм ячейка
   при 150 мм — подходит для FDM; 4096 px дали бы многогигабайтные STL без
   заметной пользы при сопле 0.4 мм).
2. Квантование median-cut до N цветов (N = 4/8/12/16 или вручную 2–16) → палитра,
   отсортированная по яркости Rec.709 (от тёмного к светлому).
3. Каждый пиксель сопоставляется ближайшему цвету палитры (расстояние redmean).
4. Поле высот: `z = base + band × step`, `step = (max − base)/(N − 1)`;
   band = `N−1−idx` (тёмный выше) или `idx` (светлый выше).
5. Меш: верхний четырёхугольник на ячейку + стенки только на перепадах высот +
   нижняя сетка по ячейкам. Вертикальные рёбра стенок разбиваются по высотам всех
   угловых ячеек («молния»), за счёт чего меш остаётся водонепроницаемым даже там,
   где сходятся четыре ячейки разной высоты.
6. Панель палитры перечисляет цвета: hex, ближайший распространённый филамент,
   порядок печати (#1 = загружается первым) и верхнюю координату Z.
7. Кнопки экспорта отдают бинарные blob'ы STL / 3MF для скачивания.

## Ключевые решения

- **Один файл, цвет высотой** (выбор пользователя): единственный STL/3MF; панель
  палитры документирует порядок печати для ручных смен филамента или AMS.
- **Свой мешер и экспорт** вместо универсальных библиотек: топология ступенчатой
  карты высот (отсечение скрытых граней, «молнии» стенок, точная
  водонепроницаемость) — это и есть ценность; библиотеки в этом мешают.
- **Цвет в 3MF через `basematerials`** (сверено со спецификацией) плюс
  `<metadata>` с палитрой и порядком печати; STL по формату остаётся без цвета.
- **Водонепроницаемость доказывается тестом:** каждое ребро меша принадлежит ровно
  двум треугольникам, а объём по теореме о дивергенции совпадает с
  Σ (площадь ячейки × высота ячейки).

## Тестирование

- `src/test/pipeline.test.ts` — 15 юнит-тестов, все проходят: полосы высот в обоих
  режимах, водонепроницаемость меша + знаковый объём + цвета граней, квантование
  (точное число, одноцветное изображение, корректность индексов), сортировка по
  яркости, round-trip hex, структура бинарного STL, структура zip 3MF + ссылки на
  материалы, логика порядка печати в обоих режимах.
- Проверено сквозным прогоном в живом предпросмотре: синтетическое изображение
  256×256 → сокращения до 4 и 8 цветов, отрисованный 3D-рельеф, оба экспорта
  (≈13 МБ STL, ≈2 МБ 3MF).

## Обработка ошибок

- Файлы не-изображения и нечитаемые изображения → ошибка в строке состояния.
- Число цветов ограничено диапазоном 2–16; максимальная высота всегда выше основания.
- Сервера нет, переменных окружения на этапе сборки нет, после загрузки всё
  работает полностью офлайн.
