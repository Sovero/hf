# Разворачивание HueForge Web (deploy)

Готовый пакет `hueforge-web-deploy-v*.zip` — это **собранное приложение**:
не нужны ни `npm install`, ни интернет, ни исходники. Только Node.js.

> **Предпочитаете обычное приложение?** Есть и настольная версия — установщик
> `hueforge-web-setup-<version>.exe` с того же релиза: окно с ярлыком, автообновление
> из GitHub Releases, нативные диалоги сохранения. См. раздел «Desktop app»
> в README. Этот файл — про вариант «сервер + браузер».

## Разворачивание на новом ПК

1. Установите [Node.js LTS](https://nodejs.org) (один раз, на весь ПК).
2. Распакуйте `hueforge-web-deploy-v*.zip` в любую папку.
3. Дважды щёлкните **`deploy.bat`** — сервер запустится и откроется браузер на
   `http://127.0.0.1:8080`.

Закройте окно консоли — сервер остановится. Другой порт: `deploy.bat 3000`.

## «Открыть в слайсере» (по желанию)

`deploy-slicer.bat` — то же самое, но с включённой передачей в слайсер:
кнопка **«Открыть в слайсере»** в разделе экспорта отправит собранный 3MF
сразу в установленный слайсер (Bambu Studio / OrcaSlicer / PrusaSlicer).

- По умолчанию функция **выключена** — обычный `deploy.bat` её не включает.
- Сервер слушает только `127.0.0.1`, и запустить чужой exe из запроса нельзя:
  приложение выбирает лишь среди слайсеров, найденных на этом компьютере.
- Слайсер не нашёлся? Укажите путь вручную перед запуском:
  `set HF_SLICER_PATH=C:\Path\To\slicer.exe` (или JSON-массив
  `set HF_SLICER_PATH=["C:\Path\slicer.exe","--flag"]` — аргументы передаются
  перед файлом модели).
- В исходниках то же самое: `set HF_ALLOW_SLICER=1` перед `npm run dev`.

Эквивалент ручного запуска: `node server.mjs 8080 --allow-slicer`.

## Как собрать такой пакет из исходников

```bash
npm run build          # создаёт dist/
npm run pack-deploy    # собирает hueforge-web-deploy-v<версия>.zip
```

`pack-deploy` кладёт в архив только то, что нужно для работы:
`dist/`, `server.mjs`, `slicer-launch.mjs`, `deploy.bat`,
`deploy-slicer.bat`, `install.bat`, `update.ps1` и этот файл.

## Что нового в v0.8.0

**Windows desktop app (Electron)**
- Появился нативный Windows-установщик `hueforge-web-setup-0.8.0.exe` (NSIS,
  x64): отдельное окно, ярлык на рабочем столе и в Start menu, без браузера и
  Node.js.
- Автообновление встроено в приложение: GitHub Releases публикует
  `latest.yml` и `.blockmap`, а приложение проверяет стабильный канал при
  старте и далее каждые 4 часа.
- Экспорт в Electron открывает нативный диалог «Сохранить как…» и сообщает
  реальный исход операции — сохранено, отменено или ошибка. Большие STL/3MF
  записываются асинхронно и не блокируют окно.
- Release workflow проверяет версию, прогоняет typecheck/тесты/build на Linux,
  собирает web-пакеты, а Electron/NSIS-установщик строит на нативном
  `windows-latest` без зависимости от Wine.

**Reference 3MF и обработка**
- Reference 3MF разбирается в Web Worker, а границы вершин передаются
  потоково — тяжёлый импорт не блокирует интерфейс.
- Добавлены исправления UI для reference 3MF и безопасные проверки пути
  обработки до построения результата.

**Проверка печатаемости**
- Хрупкие изолированные участки остаются честным предупреждением: для них
  больше не предлагается фиктивная кнопка «Исправить». Автоматически меняются
  только параметры, которые действительно можно безопасно скорректировать.
- Панель продолжает показывать проблемы тонких полос, мелких элементов и
  большого числа смен филамента с конкретными рекомендациями.

**UI и печать**
- Кнопка «По прозрачности (τ)» в палитре: толщина листов считается из
  прозрачности филамента, общая высота сохраняется.
- Все кнопки действий получили иконки; режимы 3D-вьюера (Модель / ΔE-карта /
  Срез слоя) — пиктограммы и всплывающие подсказки.
- Язык и тема в шапке — компактные кнопки с меню выбора; экспортные кнопки
  выровнены в едином стиле.
- Контраст текста в темах Nord и Solar доведён до нормы WCAG; уточнены
  подсказки о ступенчатом рельефе и порядке листов.

Номер версии `v0.8.0` виден в шапке приложения.

Предыдущие возможности сохранены: ортографический вид сверху, плита стола и
контактная тень в 3D-вьюере, палитра из катушек и автоподбор филаментов из
каталога российских производителей.

## Чек-лист обновления со старой версии

1. **Остановите старый сервер** — закройте окно консоли, где работает
   `deploy.bat` (или нажмите Ctrl+C в нём).
2. **Скачайте новый пакет** `hueforge-web-deploy-v0.8.0.zip` с GitHub
   (страница релизов) — или возьмите свежую сборку, если вам её передали
   напрямую.
3. **Распакуйте архив поверх старой папки** (или в новую папку — оба
   варианта подходят).
4. **Запустите `deploy.bat`** и дождитесь, пока откроется браузер на
   `http://127.0.0.1:8080`.
5. **Проверьте версию** в шапке приложения — должно быть «v0.8.0».
6. **Проверьте свои настройки**: язык, тема, выбранный принтер и палитра
   хранятся в браузере и сохраняются между обновлениями. Если открылся
   «чистый» вид — вы открыли приложение в другом браузере или профиле;
   настройки привязаны к браузеру, а не к файлам приложения.
7. **Быстрая проверка работы**: загрузите картинку → палитра построится →
   скачайте STL или 3MF → убедитесь, что кнопки панелей не выходят за
   границы.

Если что-то пошло не так, всегда можно вернуться: распакуйте предыдущий
архив и запустите его `deploy.bat` — старые версии пакетов совместимы.

## Обновление из исходников (необязательно)

В пакете есть и классический установщик-обновлятор **`install.bat`** (с
помощником `update.ps1`). Он нужен, если вы хотите получать свежие версии
прямо с GitHub в один клик: проверяет, вышла ли новая версия, скачивает
исходники, ставит зависимости и создаёт ярлык на рабочем столе.

1. Запустите **`install.bat`** из распакованной папки.
2. При первом запуске он может попросить **GitHub-токен** — репозиторий
   приватный, поэтому проверка обновлений без токена невозможна. Создайте
   fine-grained токен (доступ только к этому репозиторию, права
   `Contents: Read` + `Metadata: Read`) и введите его один раз — он
   сохраняется только на этом ПК (в `%APPDATA%\HueForgeWeb`).
3. Дальше при каждом запуске `install.bat` сам спросит: обновиться до новой
   версии или работать с текущей.

**Важно:** `install.bat` переводит папку в режим «из исходников» — после
первого обновления это полноценная установка с исходным кодом и dev-сервером
(нужны Node.js и интернет), а не готовый пакет. Обычным пользователям
достаточно `deploy.bat` и ручного обновления по чек-листу выше; `install.bat`
подходит тем, кто хочет автообновления с GitHub.

Первый запуск `install.bat` в свежей deploy-папке сразу предложит обновление:
номер версии определяется из исходников, которых в пакете ещё нет — примите
его, и папка станет актуальной установкой.

### update.ps1 вручную

Тот же помощник можно вызывать напрямую из PowerShell (из распакованной
папки). Команды:

- `powershell -ExecutionPolicy Bypass -File update.ps1 check` — печатает
  номер новой версии (например `v0.8.0`), если она вышла, `NEED_TOKEN` —
  если репозиторий требует токен, или ничего — если обновлений нет.
- `powershell -ExecutionPolicy Bypass -File update.ps1 save-token` —
  попросит ввести токен (ввод маскируется) и сохранит его в
  `%APPDATA%\HueForgeWeb\github_token.txt`.
- `powershell -ExecutionPolicy Bypass -File update.ps1 download v0.8.0` —
  скачает исходники версии `v0.8.0` с GitHub во временную папку и напечатает
  путь к распакованному дереву (его можно скопировать поверх текущей папки).
- `powershell -ExecutionPolicy Bypass -File update.ps1 download-deploy v0.8.0` —
  **обновление для пользователей deploy-пакета**: скачает готовый пакет
  `hueforge-web-deploy-v0.8.0.zip` с релиза и распакует его **поверх текущей
  папки** (без исходников, без npm install). После этого нужно перезапустить
  `deploy.bat`. Команда заменяет и сам `update.ps1` на новую версию, поэтому
  её можно запускать повторно в каждой новой версии.
- `powershell -ExecutionPolicy Bypass -File update.ps1 rollback` — **откат**:
  вернёт папку в состояние до последнего обновления. Перед распаковкой
  `download-deploy` сохраняет бэкап предыдущей версии в
  `%APPDATA%\HueForgeWeb\backup-deploy` (один слот — состояние до последнего
  обновления); `rollback` восстанавливает его. Откат зеркальный: файлы,
  добавленные обновлением (например, новые бандлы `dist/`), удаляются —
  папка возвращается ровно в прежнее состояние. Если бэкапа нет — команда
  сообщит об ошибке.

> **Чистая замена `dist/`:** `download-deploy` зеркалит папку `dist`
> (`robocopy /MIR`) — устаревшие файлы сборки старой версии удаляются, а не
> копятся. Файлы вне `dist/` (например, сохранённые вами конфиги) при
> обновлении не трогаются; при откате возвращается точное прежнее состояние.

Токен вместо сохранения можно задать и переменной окружения
`HF_GITHUB_TOKEN` — она имеет приоритет над файлом.

> **Важно про версии:** в deploy-пакете нет `package.json`, поэтому его версия
> лежит в файле `version.txt` (внутри пакета). Команда `check` читает его,
> чтобы понять, обновлялась ли папка — не удаляйте этот файл.

### GitHub-токен: как создать

Репозиторий `Sovero/hf` приватный, поэтому проверка обновлений и скачивание
без токена невозможны. Один раз:

1. Откройте [GitHub Settings → Fine-grained tokens](https://github.com/settings/personal-access-tokens)
   и нажмите **Generate new token**.
2. В **Repository access** выберите **Only select repositories** → `Sovero/hf`.
3. В **Permissions** → **Repository permissions** поставьте:
   - **Contents**: **Read-only**
   - **Metadata**: **Read-only** (GitHub требует его автоматически)
4. Создайте токен и скопируйте его (показывается один раз).
5. Введите его в `update.ps1 save-token` — или запустите `install.bat` и
   согласитесь на ввод токена при первом запуске.

Токен хранится только на этом ПК, в `%APPDATA%\HueForgeWeb\github_token.txt`,
и даёт доступ только на чтение этого репозитория. Если токен засветился или
больше не нужен — отзовите его на той же странице GitHub (Revoke).

## Для разработчиков

- `npm run serve` — тот же сервер для локальной проверки сборки (`node server.mjs`).
- `install.bat` / `start.bat` из репозитория запускают **dev-версию** (с исходниками
  и `node_modules`) — для доработки. Пакет deploy — для использования.
